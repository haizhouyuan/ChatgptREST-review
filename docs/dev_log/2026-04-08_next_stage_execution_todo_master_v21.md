## 1. Program objective

Turn OpenClaw from a runnable shell into a production-grade Task OS with Codex as a governed high-order execution lane.

## 2. Work packages

### I. Normalized ingress frame

- [ ] Build a first-class `task_frame` before profile routing.
- [ ] Capture objective, requested deliverable, critical unknowns, interaction posture.
- [ ] Use it as the primary route input.

### J. Native task family expansion

- [ ] Add task families for visit/cooperation prep and related operator asks.
- [ ] Stop defaulting these asks to broad generic report profiles.

### K. Codex execution-lane integration

- [ ] Define explicit escalation rules from OpenClaw to Codex.
- [ ] Make Codex a first-class execution lane, not an ad hoc fallback.
- [ ] Preserve OpenClaw as shell/closure layer.

### L. Closure compiler

- [ ] Normalize outputs across lanes into operator-ready closure.
- [ ] Ensure first-screen response is actionable.

### M. Interaction learning contract

- [ ] Define correction taxonomy.
- [ ] Store structured interaction corrections.
- [ ] Apply local learning on next similar ingress.

### N. Quality harness

- [ ] Add quality gate for raw ingress, lane routing, Codex escalation, closure, and learning.
- [ ] Block future “OpenClaw ready” claims without this gate.

## 3. Acceptance

- [ ] OpenClaw can interpret messy business ingress without manual cleanup.
- [ ] OpenClaw chooses the right first move.
- [ ] OpenClaw routes hard synthesis tasks to Codex when appropriate.
- [ ] Outputs close the loop instead of ending as essays.
- [ ] User correction changes later behavior in the intended direction.
- [ ] The quality harness is green.

## 4. Explicitly not the goal

- [ ] Turning OpenClaw into the project brain
- [ ] Rebuilding all OpenClaw-native modules from scratch
- [ ] Adding more persistent role agents as a proxy for capability
