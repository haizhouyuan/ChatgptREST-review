# 2026-04-02 Planning Knowledge Capability Value Matrix Walkthrough v1

## 这轮为什么要补这份 matrix

用户的问题已经不是：

1. “有没有做 KB”
2. “有没有做向量检索”
3. “有没有做知识图谱”

而是：

1. 到底做出了哪些能力
2. 哪些是明确服务 `planning` 的
3. 哪些对 `planning` 真有直接价值
4. 哪些只是看起来高级，但不该继续当第一主线

所以这轮不再继续写泛调查，而是把结论压成一张去留矩阵。

## 这轮怎么收口

我把相关能力按 5 层拆开来看：

1. `KB working set`
2. `planning reviewed runtime pack`
3. `EvoMap canonical knowledge`
4. `planning durable work memory`
5. `signals / observer`

这样才能把“证据层”“运行时产品”“正式知识面”“任务线程记忆”“观测信号”分开。

## 这轮最关键的收口

最重要的判断不是：

1. “向量检索没用”
2. “知识图谱没用”

而是：

1. 它们不是 `planning` 主线的第一价值来源
2. 真正最值钱的是 `planning review plane -> runtime pack -> planning-priority context -> durable work memory`

也就是说，后面如果继续做 `planning agent`，最稳的方向不是再把通用知识平台做大，而是把这条 planning 专线做稳、做实、做成默认热路径。
