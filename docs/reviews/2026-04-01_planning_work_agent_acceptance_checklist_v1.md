# 2026-04-01 planning 工作型 agent 验收清单 v1

## 目的

这份清单只服务一个目标：

> 验证“面向 `planning/` 日常工作的 agent”是否真的达到了可用标准。

它不评估通用聊天能力，不评估 opencli，不评估 CLI-Anything，也不评估未来更大的平台化想象。

## 验收对象

本轮验收对象是：

- 面向 `planning/` 仓库工作的长任务 agent
- 重点看效果，不看实现路线
- 重点验证高频工作，不追求一次覆盖全部边缘场景

## 一、总通过标准

一个场景要算通过，必须同时满足这 5 条：

1. **不理解偏**
   - 能正确识别任务类型、作用对象、输出目标
   - 有歧义时先做必要澄清

2. **不漏项**
   - 该类任务应有的关键维度都覆盖
   - 不是只给一个空泛结论

3. **口径一致**
   - 项目阶段、数字、边界、引用版本不乱
   - 能回到正确入口文件

4. **可直接使用**
   - 产物可以直接进入你的工作流，而不是只能当聊天参考

5. **可核验**
   - 关键结论能回指证据、入口或待补缺口

## 二、红线

只要触碰下面任一条，本场景直接判失败：

1. 没先识别任务类型，直接按错模版输出
2. 明显命中旧稿、归档稿、噪声目录，没走有效入口
3. 关键事实、阶段、数字、边界出现自相矛盾
4. 把“还待确认”的东西写成既成事实
5. 明显漏掉该类任务的关键部分
6. 敏感内容处理不当
7. 最终产物不能直接拿来继续工作

## 三、验收方法

### 1. 验收输入

每个场景都应提供：

- 用户任务描述
- 指定或可检索的 `planning/` 入口
- 必要输入材料
- 目标输出形态

### 2. 验收输出

每个场景都要检查：

- agent 是否先对齐意图
- 是否找对入口与口径
- 产物是否完整
- 产物是否可直接使用
- 是否沉淀了正确的记忆对象或变更对象

### 3. 验收证据

每个场景都至少保留：

1. 输入材料列表
2. 产出文件
3. 核验记录
4. 如有记忆沉淀，记录对应入口或变更单

## 四、P0 必跑场景

P0 的意思是：这一组不过，就不能说第一阶段已经做成。

### AC-01 人员规划场景

**目标**  
验证 agent 能否基于现有人员、业务方向和组织要求，做出可执行的人力规划。

**建议输入基线**

- `业务PPT/00_会议纪要/需求文档.md`
- `00_入口/专题入口/人员与绩效专题入口.md`
- `00_入口/项目台账.md` 中与组织/招聘相关条目

**期望输出**

- 一份人员规划或组织配置方案
- 至少包含：
  - 当前团队现状
  - 角色缺口
  - 招聘/编制建议
  - 优先级
  - 风险与依赖
  - 最小闭环组织建议

**通过标准**

1. 能正确理解这是“人员规划”，不是泛项目汇报
2. 不把已有人员、职责和业务背景说错
3. 不只列岗位名称，还能说明为什么需要这些岗位
4. 对招聘优先级和组织闭环有明确建议
5. 产物能直接给你继续改或拿去内部讨论

**常见失败样式**

- 把人员规划写成空泛组织愿景
- 不区分“当前人员”和“建议新增人员”
- 没有优先级与阶段性安排

### AC-02 项目现状诊断场景

**目标**  
验证 agent 能否围绕一个项目群，正确判断当前阶段、下一里程碑、主要风险和建议动作。

**建议输入基线**

- `00_入口/项目台账.md`
- `00_入口/唯一口径底座.md`
- 某项目专题入口，例如：
  - `00_入口/专题入口/机器人代工业务专题入口.md`
  - `北美镁合金结构件/2026-03-23_项目信息同步简报_董事长_v2.md`

**期望输出**

- 一份项目现状诊断或推进建议
- 至少包含：
  - 当前阶段判断
  - 下一里程碑
  - 风险与卡点
  - 需要确认的问题
  - 推荐动作

**通过标准**

1. 能先找对项目入口
2. 能引用一致的阶段与口径
3. 不把旧风险当成当前结论，也不跳过最新状态
4. 推荐动作与项目阶段匹配
5. 能明确指出哪些判断已确定、哪些待确认

**常见失败样式**

- 直接读单篇材料，不回到项目台账和口径底座
- 把“董事长摘要”当完整项目真相
- 没有下一步动作，只有摘要复述

### AC-03 研究到决策稿场景

**目标**  
验证 agent 能否把研究/调研材料转成可拍板的判断稿，而不是只做摘要。

**建议输入基线**

- `00_入口/研究主题索引.md`
- 对应研究主题的主报告
- 相关 claims / second-check / gap note

**期望输出**

- 一份决策摘要、研究结论稿或待补清单
- 至少包含：
  - 核心结论
  - 证据依据
  - 不确定点
  - 建议动作
  - 不建议动作

**通过标准**

1. 不是纯摘要，而是能形成判断
2. 证据与结论能对上
3. 知道哪里不能装作确定
4. 能把研究语言翻译成工作语言
5. 产物可直接进入领导沟通或下一步任务

**常见失败样式**

- 只抄研究稿，不形成判断
- 不标明证据缺口
- 过度自信，替用户拍了不存在的板

### AC-04 汇报材料场景

**目标**  
验证 agent 能否把复杂输入转成对上可用的汇报材料。

**建议输入基线**

- `00_入口/专题入口/业务PPT专题入口.md`
- 某一个汇报项目 `README.md`
- 对应逐页内容稿、项目台账、预算或研究底稿

**期望输出**

- 一份领导版摘要、汇报稿、逐页内容稿，或汇报结构重写
- 至少包含：
  - 汇报对象
  - 汇报主线
  - 关键数字/节点/风险
  - 建议拍板事项

**通过标准**

1. 能区分是“领导摘要”还是“执行说明”
2. 结构清楚，不是资料堆叠
3. 关键数字、里程碑与风险都在
4. 语气和信息密度符合汇报对象
5. 产物可直接拿去继续做 PPT 或发给领导

**常见失败样式**

- 把汇报稿写成研究论文
- 只讲背景，不讲判断和动作
- 忽略汇报对象

### AC-05 会议沉淀场景

**目标**  
验证 agent 能否把会议纪要/转写/情报材料沉淀成可执行工作对象。

**建议输入基线**

- `受控资料/会议录音转写/...`
- `PRJ-2026-015` 对应方案文档
- `00_入口/每次交互后的判断与核验简表.md`
- `00_入口/记忆变更单模板.md`

**期望输出**

- 一份会议沉淀结果，至少包含：
  - 核心事实
  - 风险/情报判断
  - 行动项
  - 待补调研线索
  - 是否入库、写到哪、是否需要变更单

**通过标准**

1. 不只是纪要复述，而能抽出稳定事实与行动项
2. 能区分“可入库”与“仅临时讨论”
3. 会判断是否涉及敏感信息
4. 会落到 planning 里的正确治理对象
5. 后续人接手时能继续推进

**常见失败样式**

- 把闲聊和稳定事实混在一起
- 没有行动项和后续对象
- 完全不考虑记忆分流与脱敏

## 五、P1 扩展场景

P1 不是第一天必须全过，但它们决定这条主线能不能真正成熟。

### AC-06 预算整合场景

验证是否能围绕预算入口、关键数字总表和输出稿，形成可回指的预算方案或预算解释稿。

### AC-07 项目口径变更场景

验证是否能在口径变化时，正确更新：

- 口径条目
- 项目台账
- 变更理由
- 到期动作

而不是只改正文。

### AC-08 招聘/面试评估场景

验证是否能对候选人材料、面试记录和岗位需求做综合判断，并给出：

- 适配度
- 风险项
- 建议下一步

同时处理敏感性边界。

### AC-09 长任务续做场景

验证是否能在隔一段时间后，基于上次产物继续推进，而不是重做一版新稿。

### AC-10 复盘沉淀场景

验证是否能在任务完成后，形成：

- 本次做对了什么
- 做错了什么
- 哪些信息要入库
- 哪些规则要补齐

并能挂到后续 EvoMap/记忆体系。

## 六、每个场景都要检查的 8 个问题

无论是哪一类任务，都统一检查：

1. 它有没有先识别这是哪类工作？
2. 它有没有命中正确入口？
3. 它有没有在必要时澄清意图？
4. 它有没有覆盖该任务应有的完整维度？
5. 它有没有保持口径、数字和边界一致？
6. 它有没有把结论回指到证据或明确待补缺口？
7. 它有没有把稳定信息落到正确的记忆/治理对象？
8. 这个结果你能不能直接拿来继续工作？

## 七、建议的第一轮验收顺序

为了稳扎稳打，我建议第一轮只跑 5 个场景：

1. `AC-01` 人员规划
2. `AC-02` 项目现状诊断
3. `AC-03` 研究到决策稿
4. `AC-04` 汇报材料
5. `AC-05` 会议沉淀

原因：

- 这 5 个场景覆盖了你在 `planning/` 里最核心的高频工作
- 同时覆盖了：
  - 规划
  - 项目
  - 研究
  - 汇报
  - 记忆沉淀

如果这 5 个场景都能高质量通过，说明第一阶段主线已经基本立住。

## 八、当前冻结结论

下一轮讨论如果进入“怎么验收”，就不要再泛泛说“看起来不错”。

应该直接用这句话：

> 第一阶段的 planning 工作型 agent，必须先在人员规划、项目诊断、研究决策稿、汇报材料、会议沉淀这五类高频任务上稳定通过验收；只有这些场景能做到不理解偏、不漏项、口径一致、可直接使用、可核验，才算真正做出了你要的效果。
