# 2026-04-01 planning 工作型 agent 效果要求冻结 v1

## 目的

把下一阶段第一主线压成一个可验收的效果定义：

不是先谈架构、端口、路由，而是先回答：

1. `planning/` 里到底有哪些高频工作种类
2. 一个真正有用的 agent 必须具备哪些能力
3. 它应该怎样管理记忆
4. 对这个场景来说，“高质量完成工作”到底是什么意思

## 冻结 mouthpiece

> 下一阶段第一主线，是做一个面向 `planning/` 日常工作的长任务 agent：它能接正式工作任务，读懂历史与当前现状，在确认意图后不理解偏、不漏项，按高标准产出可直接使用的规划结果，并把每次任务中的稳定信息与复盘结论沉淀成可持续复用的记忆。

## 二、这个 agent 必须具备的效果能力

### 1. 意图理解与澄清能力

这是第一位的。

高质量的第一前提不是“写得多”，而是：

- 能理解你到底要的是哪一类工作
- 能区分“要方案、要判断、要汇报、要任务拆解、要复盘”
- 如果意图有歧义，先通过少量澄清把目标对齐
- 对齐后不跑偏

对这个场景，意图理解至少要做到：

1. 识别当前任务属于哪个专题/项目群/研究主题
2. 识别要产出的文档形态
3. 识别你要的是“内部工作稿”还是“对上汇报稿”还是“对外沟通稿”
4. 识别这一轮要的是“分析判断”还是“直接产出”

### 2. 仓库导航与现状分析能力

它必须会先找对入口，再做事。

至少要能使用并理解这些对象：

- `总入口`
- `当前版本总览`
- `导航索引`
- `专题入口`
- `唯一口径底座`
- `项目台账`
- `研究主题索引`

换句话说，这个 agent 不能只是会“搜文件”，而要能判断：

- 这个主题的唯一有效入口在哪
- 当前口径是否已冻结
- 项目现在处于哪个阶段
- 下一里程碑是什么
- 风险与缺口是什么

### 3. 规划型产出能力

这是核心交付能力。

它至少要能稳定产出以下几类结果：

1. 人员规划与组织配置方案
2. 项目推进方案与阶段门禁
3. 预算与资源投入方案
4. 五年/年度规划草案
5. 调研报告与策略判断
6. 会议纪要、情报简报与行动项
7. 董事长版/领导版/执行版不同口径的材料
8. 可直接进入台账、入口、变更单的治理对象

### 4. 项目控制能力

这个 agent 不能只会写“报告”，还要能像一个 planning 助手一样控制项目叙事。

至少要能稳定识别和维护：

- 项目边界
- 当前阶段
- 下一里程碑
- 完成标准
- 主要风险
- 负责人
- 证据链

### 5. 证据与口径一致性能力

对 `planning/` 来说，这不是附加项，是硬要求。

它必须做到：

- 结论能回指证据
- 引用不乱串版本
- 同一项目在不同文档里不说出两套阶段口径
- 研究结论与汇报口径之间可回指
- 如果证据不足，要明确说“待补”，而不是脑补补齐

### 6. 表达适配能力

同一事实，表达对象不同，写法也不同。

它需要会区分：

- 给自己用的工作底稿
- 给同事协同的执行稿
- 给领导拍板的摘要稿
- 给客户或外部伙伴的沟通稿
- 给 PPT 设计链路使用的逐页内容稿

### 7. 长任务连续性能力

这个场景的任务往往不是一轮对话结束。

所以它必须能：

- 多轮推进一个主题
- 接续上次结论继续做
- 通过结构化工件而不是纯聊天记忆维持上下文
- 在阶段变化后正确更新项目现状与待办

## 三、记忆管理必须具备哪些

### A. 入口记忆

这是“先去哪找真相”的记忆。

必须优先记住：

- `总入口`
- `当前版本总览`
- `导航索引`
- `专题入口`
- `领域入口`

作用：

- 快速选定有效范围
- 避免命中旧稿和旁路材料

### B. 口径记忆

这是“这件事按什么标准说话”的记忆。

必须优先记住：

- `唯一口径底座`
- 项目级口径底座入口
- 阶段门禁定义
- 字段字典
- 引用规则

作用：

- 防止阶段、完成标准、编号、字段含义漂移

### C. 项目记忆

这是“项目现在到哪了”的记忆。

每个项目群至少要沉淀：

- `project_id`
- `project_name`
- `project_type`
- `scope_in`
- `scope_out`
- `stage`
- `milestone_next`
- `owner`
- `risk_top`
- `evidence_links`
- `last_updated`

这基本就是 `项目台账` 的工作型记忆模型。

### D. 研究记忆

这是“这个主题我们已经研究到哪、哪条结论能复用”的记忆。

至少要沉淀：

- 主题编号
- 主题名称
- 主结论
- 主报告入口
- claim ledger / second check / conflict note 入口
- 最近更新
- 当前仍未闭合的证据缺口

### E. 任务工作记忆

这是单次任务执行中的短期记忆，不是长期事实库。

它应该记录：

- 当前用户目标
- 当前输出形态
- 当前作用对象（领导/团队/客户/自己）
- 已确认的边界
- 未确认的问题
- 本轮待完成清单

这部分允许在任务结束后衰减或清空。

### F. 变更与待办记忆

这是“这次对仓库真相做了什么改动”的记忆。

对应对象：

- `记忆变更单`
- 到期动作
- 索引更新需求
- 是否需要协作发布
- 是否需要脱敏

它的作用不是记住聊天，而是记住：

- 哪些稳定信息进入了 planning
- 哪些不应入库
- 哪些需要后续动作

### G. 敏感与受控记忆

这部分必须有边界，不能为了“都记住”而乱写。

必须区分：

- 工作稳定事实
- 临时讨论
- 受控资料
- 对外不可直接暴露的信息
- 仅能脱敏后发布的信息

规则应是：

1. 敏感信息默认不进入公开协作面
2. 对外/对上材料必须能走脱敏链
3. 临时讨论不自动升格成长期记忆

### H. 复盘记忆

这是后面接 EvoMap 的基础。

每次任务结束后，至少要沉淀：

- 本次目标是否达成
- 哪些判断是对的
- 哪些返工了
- 哪些证据不足
- 哪些地方需要补口径/补入口/补台账/补模板

这部分不是写长总结，而是为后续能力改进提供结构化输入。

## 四、对这个场景，“高质量”怎么定义

你这轮的口径已经够用了，我把它收紧成 5 条。

### 1. 不理解偏

高质量的第一条，不是文笔，而是：

- 懂你要什么
- 懂这件事属于哪个专题/项目/对象
- 如果有歧义先问清
- 最后输出的东西不偏题

### 2. 不漏项

如果你要的是“全量实现”，那高质量就必须覆盖该任务应有的维度。

例如：

- 做项目方案，就不能只写愿景，不写里程碑、风险、责任、完成标准
- 做人员规划，就不能只写岗位，不写编制、职责边界、优先级
- 做汇报，就不能只有观点，没有数字、证据链、风险和下一步

### 3. 口径一致

高质量不能建立在口径漂移上。

至少要做到：

- 阶段定义一致
- 数字口径一致
- 项目边界一致
- 引用版本一致

### 4. 可直接使用

真正高质量的产物，应该能被你直接拿去：

- 继续编辑
- 对上汇报
- 发给同事执行
- 纳入台账
- 进入下一轮任务

而不是“像答案”，但不能用。

### 5. 可核验

最后一条是：

- 为什么这么写
- 引用了什么
- 依据是什么
- 哪些地方仍待补

都应该能被快速检查。

## 五、可直接用于验收的效果标准

如果后面要验收这个 agent，我建议先用这 8 个问题：

1. 它能否正确识别当前任务属于 `planning/` 的哪一类工作？
2. 它能否先找对入口文件，而不是乱搜一堆历史稿？
3. 它能否在必要时主动澄清意图，而不是理解偏后直接写？
4. 它的产出是否覆盖该类任务应有的完整维度？
5. 它是否保持项目口径、阶段、数字和边界一致？
6. 它是否能把结论回指到证据链或入口对象？
7. 它是否会把稳定信息正确沉淀到项目/研究/变更记忆里？
8. 它产出的东西是否可以直接进入你的工作流，而不是只能当聊天参考？

## 六、当前冻结结论

从效果上看，下一阶段第一主线不是“做一个通用聪明 agent”，而是做一个 **planning 工作型 agent**。

它的最小成功定义不是：

- 会聊天
- 会总结
- 会写点规划

而是：

> 能围绕 `planning/` 里的真实工作对象，正确理解任务意图，读懂入口、口径、项目和研究记忆，输出可直接使用且可核验的高标准结果，并把稳定事实和复盘结论继续沉淀回这套治理对象里。
