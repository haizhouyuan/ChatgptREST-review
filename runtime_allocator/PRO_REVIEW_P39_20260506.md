## Executive Summary

**当前版本不应进入生产或受信环境。**

虽然 144 个 pytest 全部通过，但核心执行链存在多个 P0 级问题：`/v1/execute` 主接口实测不可正常成功返回、默认探针调度器会错误地把 provider 标成不可用、配额预留失败后仍会调用模型、schema retry 失败时可能把无效输出当成功返回、默认 admin dev key 会在未配置密钥时启用。

- **P3.5/P4 主链路尚未稳定**：服务层、探针、配额、schema、安全认证都有阻断级缺陷。
- **P5–P9 大多是"接口/演示骨架"**，没有真正并入主执行路径：成本、多租户、插件、智能路由、合规审计、联邦边缘都未达到生产级闭环。
- **测试偏向 smoke/单元 happy path**，没有覆盖服务端到端成功路径、真实 provider 调用边界、失败恢复、并发配额、多租户隔离和安全滥用场景。

## Bug List (60 items)

### P0 (10 items) — 必须先修

| # | 文件:行号 | 问题 | 影响 |
|---:|---|---|---|
| 1 | `service.py:292-304` | `/v1/execute` 调用 `execute_with_fallback(..., model=...)`，但参数名是 `model_override` | 主 API 阻断级 bug |
| 2 | `service.py:332-335` | service 使用 `result.fallback_from`，但 `SkillResult` 没有该字段 | 执行成功时响应构造会 AttributeError |
| 3 | `probe_scheduler.py:37-44` | `probe_all()` 错误调用 `probe_by_protocol(pid)`，真实签名需要 `endpoint, provider_id, protocol` | 默认生命周期任务会把 provider 标为 down |
| 4 | `service.py:183-198` | service 默认启用 broken probe scheduler，`probe_interval_seconds` 默认 60 | 服务启动后约一分钟就可能错误标坏 provider |
| 5 | `skill_agent.py:413-437` | SQLite `try_reserve()` 返回 `None` 或抛异常后，仍继续调用 provider | 配额、并发、预算限制被绕过 |

## Priority-ranked Action List

### 立即执行：P0 修复

1. **冻结生产发布** — 在 P0 修完前不应发布
2. **修复 `/v1/execute` 主接口** — `model` -> `model_override`，`fallback_from` -> `fallback_chain`
3. **关闭或修复 probe scheduler** — 默认 `PAPERCLIP_PROBE_INTERVAL_SECONDS=0`
4. **修复 reservation 语义** — 没有成功 reservation 就不能调用 provider
5. **修复 schema retry** — schema invalid 的内容永远不能作为 success 返回
6. **移除默认 admin dev-key** — 生产环境强制要求显式 key
7. **closeout 真正 fail closed** — blocked 时必须 `success=false`

8. 引入统一 `ExecutionContext`
9. 统一状态存储（废弃 legacy JSON ledger）

11. P7 intelligence 降为 advisory（不能覆盖硬策略）
12. 建立 schema registry（不同 task 不同 schema）
13. 修复 service 异步边界（asyncio.to_thread）
14. 多租户与 billing 安全

### 第三批：P5-P9 产品化
