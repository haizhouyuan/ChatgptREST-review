# Reference Pattern Mapping Draft

> Worker: WP-D Design Reference Mapping
> Date: 2026-04-27
> Scope: Convert existing design reference research into business-problem patterns for Labebe
> Rule: Every pattern states what Labebe business problem it solves. No moodboard entries without mapping.

---

## Method

Each pattern is scored against:
- **Shopper Mission** — what parent job it supports
- **Category Role** — which Labebe collection or product type it elevates
- **PDP Module** — which product-detail block it informs
- **Conversion Mechanism** — how it drives add-to-cart or bundle attachment
- **Asset Need** — what image/video/copy asset must exist to make the pattern credible
- **Rejection Condition** — when the pattern becomes generic and must be discarded

## Pattern Group A: Same-Category Brand References

### A-1. Lovevery — Age/Stage Discovery Architecture

| Dimension | Mapping |
|---|---|
| **Business Problem** | Labebe has 46 SKUs across furniture, rockers, pretend-play, and activity toys. Parents do not browse by internal collection slug. They browse by "what is right for my 18-month-old." Without age-stage routing, discovery is random and PDP bounce is high. |
| **Shopper Mission** | "Find developmentally appropriate products for my child's current stage." |
| **Category Role** | Cross-collection discovery layer. Elevates rockers-ride-ons for 6–18m, pretend-play for 2–3Y, furniture for 3–6Y. |
| **PDP Module** | Age-badge cluster, "How it supports play" accordion, developmental-window callout, stage-based FAQ (e.g., "Is this right for a 2-year-old?"). |
| **Conversion Mechanism** | Age-match confidence reduces uncertainty. If PDP shows "Best for 18–36m" with a reason, parent hesitation drops and add-to-cart rises. |
| **Asset Need** | Product photography grouped by child age in situ; age-badge icon set; stage-based copy variants per SKU. |
| **What Not to Copy** | Subscription model (Labebe is not subscription); unverifiable expert authority (no "child development expert approved" without evidence); rigid 2-month kit intervals. |
| **Rejection Condition** | If the age filter is just a dropdown with no product-grouping logic or reason text, reject as generic filter. If age badges are decorative pills with no link to PDP guidance, reject as ornament. |

### A-2. Lalo — Adult-Taste Product Presentation

| Dimension | Mapping |
|---|---|
| **Business Problem** | Labebe products are for children, but purchasers are parents who care about home aesthetics. If the site looks like a primary-color toy warehouse, price tolerance collapses and gifting intent weakens. |
| **Shopper Mission** | "Buy something my child will love that also looks good in my home." |
| **Category Role** | Premium positioning across all collections. Especially critical for rockers (giftable) and furniture (room-visible). |
| **PDP Module** | Lifestyle gallery showing product in real home context; material close-up; "In your home" scale reference; bundle card with room-set photo. |
| **Conversion Mechanism** | Home-fit confidence raises AOV for furniture bundles. Gifting confidence raises rocker conversion. |
| **Asset Need** | Editorial lifestyle photography (not white-background only); room-context shots per hero SKU; material texture detail shots. |
| **What Not to Copy** | Over-minimalism that hides SKU breadth (Lalo has narrow catalog; Labebe has 46 SKUs); generic pastel SaaS feel; unbranded Scandinavian mimicry. |
| **Rejection Condition** | If the layout is clean but product variety is buried below four screenfuls of whitespace, reject as catalog-hiding minimalism. If the color palette drifts into cool greys instead of warm oak/cream/blush, reject as off-brand. |

| **Shopper Mission** | "Find a pretend-play setup that feels magical but durable." |

| **Rejection Condition** | If the storytelling is only decorative copy without bundle logic or material evidence, reject as narrative fluff. If "premium" is communicated only through price, not through scenario and material proof, reject as price signaling without substance. |

| Dimension | Mapping |

### A-5. Crate & Kids — Room-Based Merchandising

| Dimension | Mapping |
|---|---|
| **Business Problem** | Labebe sells furniture and storage that lives in rooms. If parents browse by product type alone, they buy single items. If they browse by room goal, they buy sets. Room merchandising raises basket size and positions Labebe as a room brand, not a toy brand. |
| **Shopper Mission** | "Design or refresh my child's nursery/playroom/kitchen space." |
| **Category Role** | Furniture and storage collection bundling. Cross-sells rockers into nursery sets, kitchens into playroom sets, shelves into organization sets. |
| **PDP Module** | "Complete the room" bundle strip; room-fit dimensions; color/finish coordination note; room-scene gallery. |
| **Conversion Mechanism** | Room-set bundling raises AOV. Shop-by-room landing pages capture Pinterest/SEO traffic. |
| **Asset Need** | Room-scene photography (nursery with rocker + shelf; playroom with kitchen + storage); room-set bundle hero images; before/after playroom-reset imagery. |
| **What Not to Copy** | Big-box catalog density (Crate & Kids shows many SKUs per page; Labebe should show fewer, larger, editorial); promises of real human design services. |
| **Rejection Condition** | If the room page is just a collection filter with a room name, reject as label-only merchandising. If room photography shows non-Labebe products mixed in without disclosure, reject as misleading context. |

| Dimension | Mapping |

### A-8. Nestig / Oeuf / Ferm Living Kids — Room Growth & Longevity Narrative

| Dimension | Mapping |
|---|---|
| **Business Problem** | Children's furniture is often seen as short-lived. Parents hesitate to spend $100+ on a shelf or tower if they think it is only useful for 6 months. A longevity narrative extends perceived value and justifies premium pricing. |
| **Shopper Mission** | "Buy furniture that grows with my child and lasts multiple stages." |
| **Category Role** | Furniture collection value anchor. Shelf -> toy storage -> book display. Tower -> kitchen helper -> bathroom helper. |
| **PDP Module** | Growth timeline ("Age 1: pull-up; Age 2: kitchen helper; Age 3: independent hand-washing"); longevity guarantee if available; room-set progression images. |
| **Conversion Mechanism** | Longevity framing converts "too expensive" into "worth it over time." Growth timeline increases purchase confidence for first-time parents. |
| **Asset Need** | Product-in-use across ages photography or illustration; timeline graphics; room-set progression images. |
| **What Not to Copy** | Fake Scandinavian brand claims ("Designed in Copenhagen" without evidence); heirloom promises without warranty or material proof. |
| **Rejection Condition** | If the growth timeline shows unrealistic age ranges (e.g., "birth to 12 years" for a rocker), reject as overclaim. If longevity is only stated in copy, not visualized, reject as unsupported promise. |

### D-2. Collection: Scenario-Before-Category Grid (Composite)

| Dimension | Mapping |
|---|---|
| **Business Problem** | Standard product grids sort by price or name. Parents do not shop that way. They shop by scenario ("first birthday gift," "kitchen helper," "playroom reset"). Scenario grids increase relevance and reduce browsing fatigue. |
| **Shopper Mission** | "Find products that match my specific need, not just browse everything." |
| **Category Role** | Collection page restructure. Giftable Rockers, Montessori at Home, Pretend Play Worlds, Playroom Reset. |
| **PDP Module** | "Best for" labels on collection cards; scenario tags. |
| **Conversion Mechanism** | Scenario match increases PDP click-through. Filtered grids reduce decision fatigue. |
| **Asset Need** | Collection scenario hero images; "best for" badge graphics; filter chip icons. |
| **What Not to Copy** | Big-box density (too many products per row); scenario labels without supporting PDP content. |
| **Rejection Condition** | If scenario labels are just category names renamed, reject as relabeling. If the grid shows more than 8 products above the fold on mobile, reject as density. |

### D-3. PDP: Truth-Bound Complete Product Page (Composite)

| Dimension | Mapping |
|---|---|
| **Business Problem** | Labebe PDPs must answer parent uncertainty (age fit, room fit, dimensions, assembly, safety) without inventing claims. A truth-bound PDP converts better because it reduces return risk and builds trust. |
| **Shopper Mission** | "Is this right for my child, room, budget, and occasion?" |
| **Category Role** | Universal PDP template. |
| **PDP Module** | Gallery (product + lifestyle + detail + dimension); truth drawer; age/room/occasion badges; storyboard lens; bundle strip; FAQ; materials (source-backed only); assembly/care. |
| **Conversion Mechanism** | Completeness reduces uncertainty. Bundles raise AOV. Truth drawer differentiates from Amazon listings. |
| **Asset Need** | Gallery images per SKU (min 4: product, lifestyle, detail, dimension); storyboard frames; bundle composition images; FAQ copy. |
| **What Not to Copy** | Fake reviews; fake star ratings; unverified safety certifications; invented material claims. |
| **Rejection Condition** | If any claim in the PDP lacks a source label (scraped/official/to-be-confirmed), reject per Claim Gate. If the PDP has no dimension or fit block, reject as incomplete. |

| Dimension | Mapping |
