# Labebe Radical Design Rethink

Date: 2026-04-26

## Why The Current Direction Must Be Broken

The current site is too plausible. It solves data truth, route completeness, mobile access, and basic product-to-asset storytelling, but it still reads as:

```text
warm children's DTC site + dark AI dashboard + internal presentation pages
```

That grammar does not create a decision-maker shock. The next version should make the visitor feel that AI changes the shape of the website itself, not merely the content inside a normal website.

## Fixed Core

Only one strategic idea is protected:

```text
One real SKU expands into a multi-channel product growth matrix.
```

Everything else can be rebuilt:

- palette;
- typography;
- hero;
- navigation;
- product discovery;
- PDP;
- mobile demo path;
- design library;
- AI Studio;
- presentation route.

## Stronger Design Frame

The next site should not be a polished shop with an AI section. It should be a designed performance where:

1. A product appears as a physical object.
2. The system scans its real facts.
3. The product splits into commerce, story, channel, and governance layers.
4. The viewer can still buy or inspect the product.
5. The whole action is understandable on a phone in under 30 seconds.

## Candidate Direction To Test Against Pro

Working name:

```text
Labebe Product Collider
```

Metaphor:

```text
A real SKU enters a beautiful commerce machine and collides with channel strategy, parent scenarios, product truth, and claim gates.
```

Visual language:

- dark ivory / near-black base instead of warm cream;
- high-contrast product cutouts;
- electric accent colors used sparingly for AI state;
- radial and exploded-view layouts instead of stacked sections;
- product facts as instrument labels, not paragraphs;
- matrix cards as orbiting channel plates;
- large mobile swipe performance instead of normal scroll.

First 10 seconds:

1. Full-viewport product stage.
2. Pink Unicorn Rocker floats at center with three instrument rings: `Truth`, `Shop`, `Growth`.
3. The user presses `Run Matrix`.
4. The SKU splits into seven channel assets with visible source lines.
5. Unsupported claims are rejected in-place before the final asset pack lights up.

Commerce must remain intact:

- every channel card links back to the real SKU;
- product card still exposes price, review count, source, unknown fields;
- PDP can be reached from any view;
- cart/add-to-cart remains available;
- no fake claims or fake metrics.

## What To Delete From The Previous Version

- warm DTC hero copy;
- mode switcher that only changes mood;
- card-grid-first homepage;
- separate "AI Studio" that feels like a SaaS dashboard;
- long explanatory section copy;
- design library as documentation page;
- generic "executive path" route layout;
- pastel-only color system;
- normal ecommerce section stacking.

## What To Keep

- `products.ts` grounded data model;
- 16 local SKU images;
- Product Truth / unknown fields discipline;
- route coverage;
- product matrix content;
- PDP and cart logic;
- public deployment wiring.

## Board-Level Test

The next version passes only if a viewer can say, within one minute:

```text
I see how one real product becomes a shopping experience, a content engine, and a governed AI workflow.
```

It fails if the reaction is:

```text
This is a nicer Shopify theme with an AI slide.
```
