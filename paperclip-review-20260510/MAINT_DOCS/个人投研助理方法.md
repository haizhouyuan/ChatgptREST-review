## 1. 你真正需要的是四个系统，而不是一个框架

你的目标可以拆成四块：

| 模块                | 目标                               | 最适合的技术路线                         |
| ----------------- | -------------------------------- | -------------------------------- |
| **赛道分析**          | 自动生成行业景气度、产业链、公司池、催化/风险、估值分位     | 数据管道 + 行业知识图谱 + RAG + 定期报告生成     |
| **公司研究**          | 自动读财报、公告、电话会、新闻、研报，形成可追溯 memo    | SEC/巨潮/交易所公告 + 文档解析 + LLM 结构化分析  |
| **买入点监控**         | 监控估值、技术面、事件、资金、情绪、业绩修正           | 规则引擎 + 回测引擎 + 告警系统，不建议由 LLM 直接判断 |
| **机构/博主/独立投资人跟踪** | 跟踪 13F、十大股东、基金持仓、信件、博客、X/雪球/公众号等 | 结构化持仓数据库 + RSS/网页变更监控 + 内容摘要/评分  |

最重要的工程原则是：**LLM 不直接算信号，不直接决定买入；LLM 解释信号、检查证据、生成研究结论。**

## 3. 我建议的整体架构

可以按这个架构搭：

```text
数据源层
├── 美股：SEC EDGAR、OpenBB、yfinance/FMP/Polygon/Alpha Vantage、公司 IR、电话会、13F、Form 4、新闻
├── A股：AKShare、Tushare、Baostock、巨潮、上交所、深交所、东方财富、同花顺、基金公告、北向/港股通
├── 信息源：RSSHub、Huginn、changedetection、博客、X、雪球、公众号、Substack、机构信件
└── 手工输入：你的持仓、观察池、投资原则、黑名单、行业假设

数据仓库层
├── DuckDB / Parquet：历史行情、因子、财务快照
├── Postgres：证券主数据、研究任务、告警、memo、用户配置
├── pgvector / Qdrant / Chroma：公告、年报、电话会、博文、研报向量库
├── Redis：缓存、任务状态、去重
└── MinIO / S3：PDF、HTML、图片、原始文件

工具层 / MCP 层
├── price_tool：行情、复权、涨跌停、成交量
├── fundamentals_tool：财务、估值、同比/环比、杜邦拆解
├── filings_tool：10-K/10-Q/8-K、A股公告、年报季报
├── ownership_tool：13F、Form 4、十大股东、基金持仓
├── sector_tool：行业景气指标、产业链价格、政策、库存、产能
├── backtest_tool：vectorbt/Qlib/Backtrader
└── alert_tool：价格、估值、事件、内容变化、情绪变化

工作流层
├── 赛道分析工作流
├── 公司深研工作流
├── 财报更新工作流
├── 买入点监控工作流
├── 机构/博主跟踪工作流
└── 研究复盘与评分工作流

输出层
├── 每日告警
├── 每周赛道雷达
├── 公司 memo
├── 持仓/观察池仪表盘
├── 机构/博主动态摘要
└── 买入点 watchlist
```

这个系统里，**Agent 是工作流节点，不是最高权力中心**。例如“公司研究”可以由 7 个节点组成：数据抓取 → 财务计算 → 公告/电话会 RAG → 护城河分析 → 估值 → 反方观点 → memo 生成。中间每一步都落库，方便复查。

## 4. 赛道分析的方法论框架

你的“赛道分析”不要只让 LLM 写一篇行业综述，而应该形成一个固定的行业评分卡。

### 4.1 赛道分析输出模板

每个赛道固定生成：

```text
1. 赛道定义
   - 赛道边界
   - 上游/中游/下游
   - 主要产品、服务、商业模式
   - 美股/A股可投资标的池

2. 需求端
   - 终端需求
   - 渗透率
   - 政策/补贴/监管
   - 宏观敏感性
   - 客户 CAPEX/OPEX 周期

3. 供给端
   - 产能
   - 库存
   - 原材料
   - 技术路线
   - 进入壁垒
   - 价格周期

4. 产业链利润池
   - 哪个环节议价权最强
   - 毛利率/ROIC 横向对比
   - 谁受益于量增
   - 谁受益于价格上涨
   - 谁受益于成本下降

5. 竞争格局
   - CR3/CR5
   - 市占率变化
   - 新进入者
   - 替代技术
   - 国产替代/出海逻辑

6. 景气指标
   - 订单
   - 出货
   - 价格
   - 库存
   - 资本开支
   - 招标
   - 渠道数据
   - 关键词热度
   - 相关股票相对强弱

7. 估值
   - 历史估值分位
   - 同行业估值
   - 美股/A股估值差
   - 周期高低点估值
   - 反向 DCF 隐含增速

8. 机构与聪明钱
   - 13F 新进/增持/减持
   - A股前十大股东变化
   - 基金持仓变化
   - 北向资金变化
   - 重要投资人/博主观点变化

9. 催化与风险
   - 财报
   - 政策
   - 产品发布
   - 价格拐点
   - 监管
   - 反垄断
   - 汇率/利率
   - 技术替代

10. 结论
   - 当前阶段：左侧/右侧/拥挤/冷门
   - 最值得研究的 5 家公司
   - 最需要监控的 5 个指标
   - 触发深研的条件
```

### 4.2 赛道评分卡

建议每个行业每周/每月跑一次：

| 维度 | 指标                 | 分数      |
| -- | ------------------ | ------- |
| 需求 | 订单、出货、渗透率、客户 CAPEX | -2 到 +2 |
| 供给 | 库存、产能、价格、原材料       | -2 到 +2 |
| 利润 | 毛利率、ROIC、经营杠杆      | -2 到 +2 |
| 估值 | 历史分位、相对市场、相对海外     | -2 到 +2 |
| 资金 | 13F、基金持仓、北向、成交拥挤度  | -2 到 +2 |
| 催化 | 财报、政策、产品、价格拐点      | -2 到 +2 |
| 风险 | 监管、竞争、技术替代、周期下行    | -2 到 +2 |

最后形成：

```text
sector_score = demand + supply + profit + valuation + flow + catalyst - risk
```

然后按照分数把赛道分成：

```text
A类：景气上行 + 估值合理 + 机构刚开始加仓
B类：景气上行 + 估值偏贵 + 只适合等回调
C类：景气下行 + 估值便宜 + 等拐点
D类：景气下行 + 估值不便宜 + 暂不研究
```

## 5. 公司研究的方法论框架

公司研究建议固定为一份 **Investment Memo**，不要每次让 Agent 自由发挥。

### 5.1 公司研究 memo 模板

```text
一页结论
- 公司一句话
- 当前投资结论：深研/观察/等待/剔除

- 核心空头逻辑
- 最大分歧点
- 买入触发条件
- 失效条件
- 关键监控指标

1. 公司与业务结构
- 收入分部
- 地区分布
- 客户结构
- 商业模式
- 价格/成本驱动
- 周期属性

2. 财务质量
- 收入增长
- 毛利率/经营利润率
- ROIC/ROE
- 自由现金流
- 应收/存货/预收
- 资本开支
- 负债
- 股权稀释/回购/SBC

3. 竞争优势

- 品牌

- 转换成本
- 规模经济
- 渠道

4. 管理层与资本配置

- 并购记录
- 回购/分红
- 激励机制
- 内部人持股
- 重大股东变化

5. 行业位置
- 所在赛道景气度
- 市占率

6. 估值

- 同业对比
- DCF
- 反向 DCF
- 熊/基准/牛三种情景

7. 催化
- 财报
- 新产品
- 价格上涨
- 成本下降
- 政策
- 订单
- 指数纳入
- 股东变化
- 行业拐点

8. 风险

- 竞争风险
- 监管风险
- 技术替代
- 客户集中度
- 周期下行
- 估值压缩
- 流动性风险

9. 买入点监控
- 估值条件
- 技术面条件
- 基本面条件
- 事件条件
- 仓位建议
- 止损/失效条件

10. 证据与引用
- 财报/公告
- 电话会
- 新闻
- 数据表
- 机构持仓
- 博主/投资人观点
```

A 股公司研究要特别注意披露时点。证监会《上市公司信息披露管理办法》要求上市公司披露年度报告、中期报告，年度报告内容包括主要会计数据和财务指标、前十大股东持股情况、管理层讨论与分析、重大事件、审计报告等；中期报告也要求披露主要财务指标、股东总数、前十大股东持股情况、管理层讨论与分析等。([CSPRC][26])

### 5.2 公司打分模型

建议每家公司打 6 个分数：

```text
quality_score      质量：ROIC、现金流、利润率、负债、治理
growth_score       成长：收入、利润、TAM、份额、订单
valuation_score    估值：历史分位、同业、反向DCF
catalyst_score     催化：财报、产品、政策、景气拐点
risk_score         风险：财务、竞争、监管、技术、周期
timing_score       时机：趋势、相对强弱、成交量、回撤、拥挤度
```

总分不要简单相加，建议用“硬门槛 + 软评分”：

```text
硬门槛：
- 财务造假/审计重大保留：直接剔除
- 自由现金流长期为负但估值极高：限制仓位
- 流动性太差：限制仓位
- 重大监管不确定性：进入高风险池

软评分：
final_score =
  0.25 * quality_score
+ 0.20 * growth_score
+ 0.20 * valuation_score
+ 0.15 * catalyst_score
+ 0.10 * timing_score
- 0.10 * risk_score
```

## 6. “买入点监控”应该怎么做

这里最容易踩坑。不要让 LLM 每天说“可以买/不能买”。正确做法是：**先定义可回测的买入条件，再让系统监控条件是否触发，最后让 LLM 解释触发原因和风险。**

### 6.1 买入点分三类

#### 第一类：估值型买点

适合优秀公司、消费、软件、龙头制造、现金流稳定公司。

例子：

```yaml
rule_name: valuation_pullback
conditions:
  - ev_ebitda_percentile_5y < 30
  - fcf_yield > 0.04
  - revenue_growth_ttm > 0.08
  - gross_margin_ttm_not_deteriorating: true
  - net_debt_to_ebitda < 2.5
alert:
  level: research
  message: "估值进入历史低位，检查基本面是否恶化。"
```

#### 第二类：景气拐点型买点

适合周期、半导体、光伏、化工、航运、工程机械、汽车链等。

```yaml
rule_name: cycle_inflection
conditions:
  - sector_price_index_3m_change > 0
  - inventory_yoy < 0
  - company_revenue_yoy_turn_positive: true
  - gross_margin_qoq > 0
  - relative_strength_60d > 0
alert:
  level: high
  message: "行业价格/库存/利润率可能出现拐点，触发深研。"
```

#### 第三类：趋势确认型买点

适合高景气成长股、AI、创新药、军工、机器人等。

```yaml
rule_name: trend_confirmation
conditions:
  - close > ma_200
  - close > ma_50
  - relative_strength_120d_top_quantile: 0.2
  - volume_20d_avg > volume_60d_avg
  - latest_earnings_surprise > 0
alert:
  level: watch
  message: "价格趋势确认，但需要检查估值和拥挤度。"
```

### 6.2 LLM 在买入点里的角色

LLM 应该做这些事：

```text
1. 解释为什么触发
2. 找出最近公告/新闻/财报是否支持信号
3. 找出反证
4. 对比同赛道其他公司
5. 生成“是否值得人工复核”的 memo
```

LLM 不应该做这些事：

```text
1. 直接下单
2. 直接给目标价
3. 在没有数据证据时判断“可以买”
4. 用自然语言替代回测
5. 忽略流动性、滑点、停牌、涨跌停、财报披露日
```

### 6.3 买入点监控表

建议每晚跑一次：

| 股票     | 市场 | 估值分位 | 质量分 | 景气分 | 技术分 | 机构变化 | 博主热度 | 触发规则               | 优先级 |
| ------ | -- | ---: | --: | --: | --: | ---: | ---: | ------------------ | --- |
| NVDA   | 美股 |   70 |  90 |  95 |  85 |    + |    高 | trend_confirmation | 高   |
| 688xxx | A股 |   25 |  75 |  80 |  60 |    + |    中 | cycle_inflection   | 中   |
| 300xxx | A股 |   15 |  65 |  40 |  30 |    - |    低 | valuation_pullback | 低   |

## 7. 机构、博主、独立投资人的跟踪方法

### 7.1 美股机构跟踪

美股最核心是：

```text
13F：机构季度持仓
13D/13G：5%以上持股
Form 4：内部人交易
Schedule 14A / proxy：治理和股权激励
8-K：重大事件
10-K/10-Q：财务与风险
股东信：Berkshire、Oaktree、Pershing Square 等
```

Form 13F 的限制必须内置到系统里：它要求在季度结束后 45 天内披露，报告的是 13(f) securities，通常包括交易所股票、部分期权/权证、封闭式基金、部分可转债等；你可以通过 SEC EDGAR 检索 13F。([Investor][27]) SEC 也提供 13F 数据集，数据来自 EDGAR 中 XML 部分，按扁平格式发布，并且提示这些数据不能替代完整 filings，投资前应查看完整申报文件。([SEC][28])

所以你的系统里应该给 13F 打上标签：

```text
13F 信号等级：
A：多季度连续增持 + 仓位占比提升 + 多家优质机构共同买入
B：单季度新进 + 仓位较小
C：滞后披露，无法判断当前是否仍持有
D：疑似对冲腿，无法单独解释
```

### 7.2 A 股机构跟踪

A 股没有美股 13F 这种统一、完整、标准化的机构持仓披露，但可以用这些替代：

```text
1. 上市公司年报/半年报/季报中的前十大股东、前十大流通股东
2. 公募基金季报/半年报/年报中的重仓股
3. QFII、社保、险资、私募等出现在前十大股东的变化
4. 北向资金/沪深港通持股变化
5. 大宗交易
6. 龙虎榜
7. 调研活动记录
8. 定增、回购、股权激励、员工持股计划
```

证监会的信息披露规则明确要求年度报告披露前十大股东持股情况，中期报告也要求披露股东总数、前十大股东持股情况等内容。([CSPRC][26]) AKShare 的 A 股数据文档也覆盖沪深港通持股、机构排行、年报季报、业绩预告、巨潮资讯公告、股东增减持、A 股公告、财务报表等接口，适合做 A 股跟踪数据层。([AKShare][29])

### 7.3 博主/独立投资人跟踪

建议做一个 `people_sources` 表：

| 字段                  | 含义                               |
| ------------------- | -------------------------------- |
| person_id           | 投资人/博主 ID                        |
| name                | 名称                               |
| platform            | X、雪球、公众号、Substack、博客、YouTube、播客等 |
| source_url          | 信息源                              |
| rss_url             | RSSHub 或原生 RSS                   |
| credibility_score   | 可信度                              |
| style               | 价值、成长、宏观、量化、事件驱动、A股短线等           |
| horizon             | 持仓周期                             |
| markets             | 美股/A股/港股/全球                      |
| tracked_keywords    | 关键词                              |
| linked_tickers      | 历史提及股票                           |
| false_positive_rate | 噪声率                              |
| notes               | 人工备注                             |

每条内容入库后做结构化：

```text
1. 他说了什么？
2. 提到了哪些股票/行业？
3. 是观点、数据、传闻、持仓、复盘，还是情绪表达？
4. 与他之前观点相比，有没有变化？
5. 是否有数据证据？
6. 是否与其他优质来源交叉验证？
7. 对我的观察池有什么影响？
```

不要只追“谁很牛”，要追踪“这个人在什么场景下有效”。例如：

```text
A 投资人：早期发现产业趋势强，但估值纪律差
B 博主：财报拆解强，但宏观判断弱
C 机构：半导体产业链深，但经常偏卖方乐观
D 独立投资人：小盘成长强，但流动性风险高
```

## 10. 你可以采用的 Agent 分工

我会这样设计：

```text
1. Data Engineer Agent
   负责抓取、清洗、检查数据，不做投资判断。

2. Sector Analyst Agent
   负责赛道定义、产业链、景气指标、竞争格局。

3. Company Analyst Agent
   负责公司财务、业务、管理层、竞争优势。

4. Valuation Agent
   负责 DCF、相对估值、历史分位、反向 DCF。

5. Catalyst & Risk Agent
   负责催化、风险、失效条件、反方观点。

6. Quant Signal Agent
   负责调用 Python/Qlib/vectorbt，不直接口算。

7. Institution Tracker Agent
   负责 13F、十大股东、基金、北向、内部人、调研记录。

8. Influencer Tracker Agent
   负责博主、独立投资人、机构信、播客、公众号、雪球等内容摘要。

9. Memo Writer Agent
   负责把结构化结果写成固定格式 memo。

10. Evidence Checker Agent
   负责检查每个结论是否有来源、数据是否一致、是否存在幻觉。

11. Human Review Gate
   重要结论必须进入人工审核队列。
```

最重要的是最后两个：**Memo Writer + Evidence Checker**。很多投研 Agent demo 看起来很漂亮，但最大问题是“结论无法追溯”。你的系统必须做到每一句关键结论都能点回原始公告、财报、数据表或原文。

## 12. 美股和 A 股的数据差异要单独处理

### 美股注意点

```text
1. ticker 会变，CIK 更稳定
2. 13F 用 CUSIP，需要映射到 ticker
3. 13F 有 45 天滞后，且不完整反映空头和衍生品
4. 10-K/10-Q/8-K 结构化程度较高，适合自动处理
5. 20-F/6-K 覆盖很多 ADR/外国公司
6. insider trading 可以用 Form 3/4/5
7. 股票拆分、回购、SBC、稀释要单独处理
```

SEC 官方开发者页面说明，EDGAR 的 HTTPS 文件系统可访问公司、基金和个人 filings；EDGAR 搜索结果还能通过 RSS feeds 订阅，例如订阅某家公司最新 filings 或按 filing type 过滤。([SEC][30])

### A 股注意点

```text
1. 财报披露日非常关键，不能用报告期日期做回测
2. 涨跌停、停牌、ST、退市风险会影响成交
3. 前复权/后复权/不复权口径要统一
4. 业绩预告、业绩快报对股价影响很大
5. 前十大股东和基金重仓披露有滞后
6. 调研活动记录有信息价值，但容易拥挤
7. 龙虎榜更偏短线，不宜和长期基本面混用
8. 同一个公司可能同时有 A/H/ADR，需要映射
```

## 13. 研究质量评估体系

你的投研助理必须有复盘，否则会变成“每天生成很多漂亮废话”。

### 13.1 对每份 memo 打分

```text
accuracy_score：事实是否正确
evidence_score：证据是否充分
novelty_score：有没有增量信息
decision_usefulness：是否帮助决策
timeliness_score：是否及时
risk_awareness：是否列出关键风险
follow_up_score：是否给出明确监控指标
```

### 13.2 对每个信号回测

```text
1. 触发后 1D / 5D / 20D / 60D / 120D 收益
2. 相对行业收益
3. 最大回撤
4. 胜率
5. 盈亏比
6. 不同市场环境下表现
7. 不同估值分位下表现
8. 信号衰减速度
9. 交易成本和滑点
10. 是否存在幸存者偏差
```

### 13.3 对博主/机构打分

```text
1. 提前性：是否早于市场反应
2. 准确性：观点后续是否被验证
3. 稳定性：是否经常反复横跳
4. 可操作性：是否有明确逻辑和条件
5. 风格匹配：是否适合你的投资周期
6. 噪声率：无效内容比例
7. 独立性：是否只是复述市场共识
```

## 14. 最小可行版本应该怎么做

我建议你的 MVP 不要太大，先做这几件事：

### 第 0 版：观察池 + 数据仓库

```text
1. 建一个 watchlist：美股 50 只，A股 100 只以内
2. 建 securities / prices / fundamentals / filings / alerts 几张表
3. 接入 SEC、AKShare、Tushare、Baostock
4. 每天自动更新行情、估值、公告
5. 能生成一张观察池 dashboard
```

### 第 1 版：公司研究自动化

```text
1. 对每只股票生成 company profile
2. 自动抓最新财报/公告
3. 自动生成标准 memo
4. 每次财报后自动生成 update memo
5. 所有结论带证据链接
```

### 第 2 版：买入点监控

```text
1. 先只做 5 条规则：
   - 估值分位进入历史低位
   - 股价回到 200 日线以上
   - 相对行业强度转正
   - 最新财报超预期
   - 重要公告/机构增持触发

2. 每条规则必须能回测
3. 每个 alert 由 LLM 写解释，但不直接给交易指令
```

### 第 3 版：赛道雷达

```text
1. 先选 10 个赛道
2. 每个赛道建立标的池
3. 每周生成行业景气评分
4. 每周输出“值得深研公司 Top 10”
```

### 第 4 版：机构/博主跟踪

```text
1. 美股先跟踪 20 家机构的 13F
2. A股先跟踪前十大股东、基金重仓、北向持股
3. 博主先跟踪 30 个高质量来源
4. 每天生成“观点变化摘要”
5. 把观点映射到你的 watchlist
```

## 15. 最容易踩的坑

```text
1. 一开始就做全市场扫描
   结果数据质量、速度、解释能力都会崩。先做小股票池。

2. 过度迷信多 Agent 辩论
   多 Agent 很容易互相编故事。关键结论必须由数据和引用支撑。

3. 没有 point-in-time 数据
   回测时用了未来财报、未来指数成分、未来股东名单，结果全是假的。

4. 没有处理 A股涨跌停和停牌
   买点触发不代表能成交。

5. 用 LLM 做数学
   估值、回测、财务指标必须用 Python 代码计算。

6. 把 13F 当实时持仓
   13F 至少有季度披露滞后，只能当 idea source，不能当实时跟单依据。

7. 博主跟踪没有评分机制
   信息源越多，噪声越大。必须给每个人建立历史表现画像。

8. 没有反方观点
   每份 memo 必须包含 bear case 和 thesis invalidation。

9. 没有人工审核门
   高置信度不等于正确。重要 alert 应进入人工复核。
```

## 16. 我会给你的最终推荐组合

优先级从高到低：

```text
第一优先级：
LangGraph + FastAPI + Postgres + DuckDB + pgvector
OpenBB + SEC EDGAR + AKShare + Tushare + Baostock
vectorbt + Qlib
RSSHub + changedetection.io

第二优先级：
EdgarTools
Backtrader / Lean
QuantStats
PyPortfolioOpt / Riskfolio-Lib
Huginn / n8n

第三优先级：
FinRobot：借鉴公司研报生成
Dexter：借鉴任务分解和自校验
Agno investment-team：借鉴投资团队角色设计
ai-agent-moat：借鉴护城河分析
Earnings Call Analyzer：借鉴 SEC RAG 问答
Octagon / LangAlpha：借鉴 MCP 工具层设计
FinGPT / FinRL：做金融 NLP、情绪、强化学习实验，不建议作为核心系统底座
```

一句话结论：**你的个人投研助理应该是“数据可信、信号可回测、结论可追溯、观点可复盘”的投研操作系统。Agent 框架只是外壳，真正的护城河是数据结构、研究模板、监控规则、复盘机制和你的投资方法论。**
